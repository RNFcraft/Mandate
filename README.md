# Mandate: прототип карты

Из папки `game`:

```sh
npm install
npm run build
npm run build:adm2
npm start
```

Открыть http://127.0.0.1:3000. `build:adm2` выполняется один раз и при обновлении географических источников.
`npm start` пересобирает только Natural Earth и клиент, пространственное сопоставление ADM2 при старте не выполняется.
`npm run build` — отдельная сборка. `npm test` — браузерная проверка в установленном Google Chrome.
Для другого браузера измените `channel` в `playwright.config.cjs`.

ЛКМ: выбор региона; зажатая ЛКМ: перенос; колесо: масштабирование вокруг курсора (1–64×).
Полноэкранный Canvas работает в половинном разрешении с CSS `image-rendering: pixelated`.
Карта перерисовывается только при изменениях. Path2D кеширует геометрию;
пространственная сетка ограничивает число проверок попадания курсора; невидимые полигоны пропускаются.
Проекция равнопромежуточная цилиндрическая, без повторения мира по горизонтали.

Код: `client/map/`. Сборка: `scripts/build-map.cjs`; отдельный HTTP-сервер: `scripts/serve-map.cjs`.
Библиотеки: d3-geo, topojson-client; подготовка данных: mapshaper; сборка JS: esbuild; тесты: Playwright.
Исходные Natural Earth 1:10m shapefile в `data/map/` читаются без изменений.
Общая топология упрощается до 12% с сохранением форм малых регионов; клиент не загружает лишние атрибуты.
Подготовленная геометрия: `client/data/world.topo.json`.
Названия и стабильные ID базовых территорий: `client/data/adm2/hierarchy.json`.
`client/data/geography.json` описывает прежние ADM1 и нужен для поддержки старых файлов.
`client/data/state.json` — только вспомогательный современный импорт, приложение его не загружает.
ID групп ADM1 — `adm1_code`; базовые ID — `gb:<shapeGroup>:<shapeID>`.
ID политических государств задаёт сценарий, их список не зашит в код.
Сборка проверяет уникальность географических ID; загрузка и сохранение сценария проверяют владельцев и столицы.

`window.mandateMap.model.setOwner(regionId, countryId)` меняет владельца и пересчитывает границы переходов между владельцами.
Политическая раскраска и государственные границы всегда определяются `ownership` выбранного сценария.
Общая топология ADM2 задаёт соседство: один владелец — тонкая внутренняя граница,
разные владельцы — толстая государственная. `null` означает нейтральный регион.
Admin 0 используется только как нейтральная подложка суши, а не как источник политического владения.
`model.setColor(countryId, '#rrggbb')` меняет цвет страны.
`mandateMap.addLayer((context, map) => { ... })` добавляет слой в мировых координатах (360×180);
возвращает функцию удаления слоя. Событие Canvas `regionselect` содержит `detail.regionId`.
Геометрия, названия регионов и текущие владельцы разделены.

Natural Earth отражает современные административные границы, а не исторический мир 1700 года.
Исторически точный сценарий, экономика, политика, LLM и игровые объекты не реализованы.
Существующий `server.js` с llama.cpp не изменяется и для карты не запускается.

Браузерный тест проверяет загрузку всех 258 стран и 4596 регионов, цвет океана,
наведение и смену выбранного региона, сохранение выбора, перенос без случайного клика,
привязку zoom к курсору, оба предела масштаба, resize с сохранением центра,
смену владельца и пересчёт границ, время рендера и отсутствие ошибок консоли.
Скриншот после теста: `test-results/world-map.png`.

## DEV-редактор сценариев

Открыть http://127.0.0.1:3000/?editor=1&scenario=1700.
Без `editor=1` панель отсутствует. `/?scenario=1700` открывает тот же сценарий в обычном режиме;
по умолчанию загружается `modern`, самостоятельный сценарий современного импорта.

Первоначально созданный шаблон `1700` был пустым; уже сохранённые государства и территории не сбрасываются.
Для нового сценария в панели укажите отдельный ID, год и название;
«Новый пустой» создаёт новый сценарий в памяти. Разверните «+ государство», заполните ID/tag,
название, короткое название, цвет и форму правления. После создания выберите государство в списке.
В режиме «Территории» ЛКМ и drag назначают территории. При zoom ≥ 8× редактируются отдельные ADM2;
при меньшем масштабе назначаются все дочерние ADM2 выбранного ADM1. Это позволяет массовую раскраску без тысяч кликов.
«Удалить владение» возвращает единицы в нейтральное состояние.
В режиме «Столица» клик по своей территории назначает столицу. При передаче столицы прежний столичный статус снимается.
ПКМ или средняя кнопка переносят карту в любом режиме; режим «Перемещение» также позволяет перенос ЛКМ.
Undo/Redo хранит до 100 операций; один проход кисти — одна операция. В истории хранятся изменения владельцев,
а не 100 полных копий мирового ownership. История не сохраняется на диск.

Нажмите «Сохранить», чтобы записать данные на диск. «Сохранённые» → «Загрузить» открывает сценарий с диска;
несохранённые изменения при загрузке требуют подтверждения. Перезагрузка страницы не сохраняет изменения автоматически.
Изменение ID и сохранение создаёт отдельный сценарий; существующий сценарий с тем же ID заменяется.
Сборка создаёт шаблоны только при их отсутствии и не перезаписывает сохранённые сценарии.

```text
scenarios/<id>/
  scenario.json    # id, name, year, version, geography
  countries.json   # список государств
  ownership.json   # { "gb:ARG:<shapeID>": "TAG", "fallback:<adm1ID>": null, ... }
  controllers.json # необязательный будущий слой контроля
```

Государство: `{ id, name, shortName, color, capitalRegionId, governmentType }`.
`capitalRegionId` может быть `null` или ID базовой территории. `ownership` v2 содержит все 49 882 базовых ID.
Версия сценария — 2, `geography` — `mandate-adm2-v1`.
Геометрия общая для всех сценариев и не копируется. `owner` — юридический владелец;
необязательный `controllers` хранится отдельно и сохраняется без реализации оккупации.

`client/scenarios/store.js` — клиент загрузки/сохранения;
`client/editor/editor.js` — DEV-панель и история;
`shared/scenario.cjs` — общая проверка формата для браузера и сервера;
`scripts/scenarios.cjs` — локальный файловый API.
Сервер проверяет формат, ID, владельцев и столицы, сначала пишет временную папку,
затем заменяет папку сценария; чтения и записи сериализованы, ошибки замены откатываются.
Для отключения записи задайте `MANDATE_DEV_EDITOR=0` перед запуском.

`npm test` дополнительно проверяет создание государств через интерфейс, покраску нескольких регионов,
Undo/Redo, столицу, передачу и удаление владения, изменение границ, цвет полигона,
сохранение JSON, отказ при некорректном владельце, загрузку после перезагрузки страницы и перезапуска сервера,
обычный режим без панели, pan/zoom и неизменность геометрии/shapefile по SHA-256.
Скриншот редактора: `test-results/scenario-editor.png`.

Ограничения: редактор локальный, без совместной работы и истории версий файлов.
Изменение данных существующего государства, удаление государств, разделение полигонов и историческая реконструкция
пока не реализованы. Сценарии любых лет начиная с 1700 создаются вручную на подготовленных территориальных единицах.

## ADM2, иерархия и LOD

Исходный файл: `data/source/adm2/geoBoundariesCGAZ_ADM2.geojson` (550 446 979 байт).
Он читается потоково только офлайн-скриптом `scripts/build-adm2.cjs`; HTTP-сервер обслуживает папку `client`,
поэтому исходник и серверная мировая ADM2-топология не доступны как runtime-ресурсы браузера.

`npm run build:adm2` создаёт:

- `client/data/adm2/hierarchy.json`: ADM0, ADM1 и метаданные ADM2 (без геометрии и владельцев);
- `client/data/adm2/manifest.json`: индекс реальных пространственных границ чанков, размеры и отчёт;
- `client/data/adm2/chunks/*.json`: TopoJSON, сетка 5° и пакеты максимум по 400 территорий;
- `data/processed/adm2/detail.topo.json`: общая топология для проверки/подготовки;
- `data/processed/adm2/coarse.topo.json`: серверная топология для объединённых политических контуров;
- `data/processed/adm2/matching.json`: аудит пространственного сопоставления;
- `data/processed/adm2/report.json`: SHA-256 исходника, количества и размеры.

На этом наборе: 49 349 ADM2 и 533 резервные единицы для ADM1 без сопоставленных детей;
874 чанка, 27,26 МБ геометрии чанков, 5,99 МБ метаданных, максимум 306 КБ на чанк.
Серверные detail/coarse-топологии: 23,01/9,98 МБ; аудит сопоставления: 15,69 МБ.
Размеры указаны в десятичных МБ. Временные GeoJSON после сборки удаляются.

Иерархия хранится независимо от политики: `{ id, name, adm0Id, adm1Id, chunkId }`.
Для географии без ADM2 используется явный `fallback:<adm1ID>` с `fallback: true`, а не выдуманный ID geoBoundaries.
Сопоставление ADM1 использует пространственную сетку и голосование по внутренним scanline-точкам,
учитывает отверстия и исходный тег страны; для микро-государства с единственным ADM1 применяется его единственная группа.
732 единицы остались с `adm1Id: null`; 4790 имеют неоднозначное сопоставление. Confidence и исходный ADM0 сохранены в аудите.
При обновлении источника следует проверять этот аудит; совпадение современных и исторических границ не предполагается.
ID устойчивы при повторной сборке того же источника, а не гарантированы между разными релизами geoBoundaries.

Геометрия ADM2 упрощается топологически с интервалом 500 м и сохранением малых форм;
серверный дальний вариант дополнительно упрощён до 6 км. Пиксельный Canvas и палитра сохранены.

| Масштаб | Отображение и загрузка |
| --- | --- |
| 1–2,5× | Объединённые политические полигоны; ADM2-чанки не запрашиваются; внутренние ADM1-линии скрыты |
| 2,5–8× | Добавляются тонкие границы ADM1; ADM2-чанки ещё не запрашиваются |
| 8–64× | Чанки пересекающей экран географии подгружаются лениво; ADM2 доступны для hover/selection и редактора |

`client/map/lod.js` ограничивает загрузку четырьмя параллельными запросами, отменяет устаревшие запросы,
повторно использует чанки и хранит LRU-кэш максимум из 128 чанков / 12 МиБ сериализованных данных.
Фактическая память Path2D и JS-объектов больше размера JSON, но число объектов ограничено вместе с чанками.
При отдалении активных ADM2 становится ноль; кэш остаётся ограниченным. Если видимая область превышает лимит,
ближняя детализация предоставляется ближайшим чанкам, остальные сохраняют политический LOD; DEV-панель предлагает приблизить.
Ошибка загрузки не вызывает бесконечных повторных запросов.
Чанки содержат глобальные ссылки на соседей арок, поэтому края чанков не превращаются в государственные границы.

`scripts/political-worker.cjs` объединяет базовые территории по ownership настоящим polygon union (`dissolve2`),
включая пересечения резервной географии. Политические контуры на дальнем масштабе не требуют загрузки ADM2 в браузер.
Пересчёт выполняется в Node worker и объединяется после серии редакторских изменений;
локальная близкая раскраска обновляется сразу. Дальний политический слой обновляется асинхронно.
`map.lod.stats()` и `map.politicalComputeMs` доступны для диагностики.

## Совместимость сценариев и проверки

Старые v1-файлы не переписываются при чтении, сборке или запуске. При загрузке каждое владение ADM1
распределяется на сопоставленных детей, несопоставленные единицы остаются нейтральными.
Для прежней столицы выбирается представитель её дочерних территорий; сохраняются
`legacyCapitalRegionId` и `capitalMigration: representative-child`, поскольку координат исторической столицы нет.
После ручного выбора ADM2 столица привязывается непосредственно к нему.
При первом явном сохранении старого сценария в v2 создаётся исходная копия в `scenarios/.legacy-backups/<id>/`.
`controllers`, если присутствуют, мигрируют и сохраняются отдельно; механика контроля не реализуется.

Тесты запускают отдельный сервер на порту 3010, не используя состояние пользовательского сервера.
`tests/lod.spec.cjs` проверяет отсутствие мировых ADM2-запросов на дальнем/среднем масштабе,
ленивую загрузку, переходы между странами, повторное посещение, лимиты кэша, быстрый zoom/pan,
resize, SHA-256 исходника, уникальность ID и сохранность старого ownership.
Профиль сохраняется в `test-results/lod-profile.json`; долгие задачи браузера — в `test-results/lod-long-tasks.json`.
Повторная сборка проверена побайтово по 885 файлам, включая сценарии: отличий не обнаружено.
Результат сравнения: `test-results/adm2-repro-result.json`.

В последнем прогоне Chrome, viewport 1440×900: медиана JS-отрисовки мира 0,8 мс,
Европы 3,1 мс, плотной Румынии 6,4 мс (7700 активных территорий).
После путешествия кэш достиг 128 чанков, около 7,9 МБ JSON; при отдалении активных ADM2 — ноль.
Создание объединённых политических контуров занимает около 1,5 с в серверном worker;
это асинхронная операция после изменения ownership, а не стоимость каждого кадра.
Профиль содержит также максимумы времени и интервалы animation frame: в headless-среде
интервалы заметно выше времени JS-отрисовки, поэтому эти числа не означают стабильные 60 FPS.
Полная память браузера, память графического драйвера и FPS на пользовательском оборудовании отдельно не измерялись.

Ограничения: два источника имеют несовпадающие границы и неодинаковую административную детализацию.
Резервные ADM1-полигоны могут пересекаться с ADM2; polygon union устраняет внутренние линии одинакового владельца,
но конфликтующие владения в таких областях требуют ручной проверки и будущего уточнения географической основы.
Сопоставление групп приблизительное, а не географическое разрезание ADM2 по ADM1.
Микротерритории могут быть невидимы в упрощённом дальнем LOD; близкая геометрия всех базовых единиц сохранена.
Историческая реконструкция и остальные игровые системы не реализованы.
