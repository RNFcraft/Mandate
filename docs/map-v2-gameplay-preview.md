# Map v2: first gameplay-province generation pass

**Superseded.** The atomic-union geometry below was rejected visually. The
current Map v2 default uses [independent geometry](map-v2-independent-preview.md)
with the [~5,000-province tuning pass](map-v2-geography-tuning.md).
The old generator remains a debug implementation and now writes to
`client/data/map-v2-legacy` by default.

This is a separate, tunable preview. Atomic IDs, scenario ownership, saves,
population and the published geography remain authoritative and unchanged.
`preview:*` IDs are temporary and can change with inputs or configuration.

## Run

From the repository root:

```powershell
node --max-old-space-size=8192 scripts/gameplay-provinces.cjs
node --max-old-space-size=8192 scripts/gameplay-provinces.cjs --qa
npm start
# Open http://127.0.0.1:3000/?mapPreview=gameplay
npx playwright test tests/gameplay-provinces.spec.cjs
npm test
```

`--qa` regenerates and validates the artifacts from the same canonical inputs;
it is not merely a reader of the last report. Structural failures produce exit
code 1. `--help` describes the CLI. The JSON report contains IDs for warnings.

```powershell
node scripts/gameplay-provinces.cjs --target 10000 --out tmp/map-v2-10000
node scripts/gameplay-provinces.cjs --target 15000 --out tmp/map-v2-15000
node scripts/gameplay-provinces.cjs --config tmp/map-v2-config.json
```

All tuning parameters live in exported `DEFAULTS` in
`scripts/gameplay-provinces.cjs`; a configuration file overrides those keys.
Example: `{"target":12000,"densityExponent":0.35,"internalRetain":0.6}`.
`internalRetain:1` disables simplification. `--out` is an output directory;
the browser reads the default `client/data/map-v2` directory.

## Sources and artifacts

* Topology: `data/processed/canonical/atomic.topo.json`, generated by
  `scripts/canonical-mesh.cjs` and published through
  `scripts/publish-canonical.cjs`. It contains 52,262 territories. IDs include
  `gb:*` and `residual:*`; they are copied exactly, never reconstructed.
* Existing runtime hierarchy: `client/data/adm2/hierarchy.json`, geography
  `mandate-atomic-v1`. This preview does not replace or edit it.
* Adjacency: positive-length shared canonical arcs, with summed shared-border
  length. Point contacts do not create edges. The existing ADM2 chunk adjacency
  helper is not used because it also handles fallback overlaps.
* Population: sum of `cohorts[].count` by `territoryId` in
  `data/population/baselines/1700/population.json`. No cohort means zero, as in
  the existing population subsystem. The baseline geography hash must match
  the canonical topology. Total population is 591,714,189.
* Area and centroid use the repository's cylindrical equal-area approximation;
  centroid calculation includes holes. Land components are graph components.
  `coastal` means an exposed topology edge: lake shores also qualify. It is
  not a marine classification. Existing multipart atoms stay indivisible.

Generated under `client/data/map-v2/`:

| File | Purpose |
| --- | --- |
| `mapping.json` | Canonical output of this pass: atomic ID → temporary province ID |
| `provinces.json` | Atom count, substrate area/population, compactness, components, true land adjacency |
| `atoms.json` | Atomic statistics, centroid, component index, exposed-boundary flag, land neighbors |
| `maritime.json` | Island membership relations with anchor atom and distance; separate from land edges |
| `provinces.topo.json` | Shared-arc unions, encoded with the existing lossless topology codec |
| `qa.json` | Metrics, warning IDs, source/config/mapping hashes, validation methods |

The browser uses the existing `WorldMap` renderer and its pan/zoom/hit testing.
It fetches only province topology, metadata and QA. It does not load scenarios,
simulation, ADM2 chunks or political ownership. Greedy adjacency coloring
distinguishes neighboring provinces. Hover and click show basic statistics.

## Algorithm

1. Sort atomic IDs using ASCII ordering. Sum cohort counts, compute area,
   equal-area centroid and positive-length shared-arc adjacency.
2. Density weight is `(densityFloor + population / area)^densityExponent`.
   Weighted mass is area × weight. Dense regions have shorter physical seed
   spacing. No random placement is used.
3. Seed each eligible land component, then perform incremental graph-distance
   farthest-point placement. Edge cost is centroid distance × square root of
   mean density weight. Tiny single-atom components wait for maritime grouping.
4. Grow from seed frontiers on the adjacency graph. Cost includes weighted
   travel distance, province mass relative to target mass, and distance from
   seed for compactness. Every assignment has a same-province land predecessor.
5. Repair tiny single-atom territories and minority-border tails/enclaves.
   Before a transfer, check that the donor's affected land component stays
   connected. Never split atoms. Run a bounded number of repair iterations.
6. Attach tiny disconnected components to nearby exposed-boundary atoms within
   the maritime radius. Record membership separately; never add land edges.
   Remote components outside the radius remain explicit warnings.
7. Union members with `topojson-client.mergeArcs`; subset with existing
   `shared/topology-arcs.cjs`. Shared borders retain the same arc references.
8. Simplify one shared Mapshaper ArcCollection with weighted Visvalingam.
   Lock exterior vertices and arc endpoints, preserve polygon shapes, repair
   intersections and independently scan segments. Restore offending whole arcs
   if vertex repair is insufficient; reject simplification if crossings remain.

Seeds are approximately the target count; cleanup can reduce it and remote
islands can add provinces. The target is a tuning control, not a strict quota.

Overlap validation inherits the existing independent intersection + mosaic
certificate only when its topology SHA256 matches the actual input. An exact
shared-arc partition preserves that coverage. Simplification keeps the exterior
fixed and checks that no segment crossings are introduced. This is not a new
all-pairs polygon intersection audit of every final province; the report states
the validation method. Population and reported area remain sums of source
atoms even after display geometry is simplified.

All holes are conservatively flagged; the report does not claim to distinguish
natural lakes from accidental holes. Compactness uses original union perimeter
and source area. Single-atom provinces can be legitimate dense territories or
indivisible large source units. Tiny border counts are per province occurrence,
so a shared arc may occur twice. Graph connectedness cannot repair multipart
fragments already inside an indivisible source atom.

The largest territory is the existing Antarctic atom
`gb:ATA:39004313B39422738209134` (about 11.97 million km²). Large Canadian and
Greenland atoms also limit spatial refinement. Reducing them would require
splitting the substrate and is outside this aggregation pass.

Before tuning, inspect Europe, India, eastern China and Japan for overly small
or elongated provinces; Siberia, Sahara, interior Canada and Australia for
scale differences; Indonesia, the Caribbean and remote ocean islands for
grouping and tiny remaining territories. Check the QA-listed holes, tails and
compactness warnings at close zoom, especially along coastlines and the
dateline. The first pass still retains substantial modern ADM shape structure.

Validation: the complete existing suite plus the initial four new tests passed
(192 tests). After centroid/simplification changes, the five generator/preview
tests and three map/mesh regression tests were rerun successfully. This is a
first visual generation pass, not a Map v2 freeze.
