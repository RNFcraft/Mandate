# Economy v3.2: устранение повторных вычислений

Технический патч относительно `d59dfb5508fd5ed69cca6d10440d602ca1c5a365`. Экономические коэффициенты и порядок применения решений сохранены. Измерений скорости и запусков симуляции при реализации не проводилось.

## Источники избыточной работы и изменения

- `economy-routes.opportunities`: BFS выполнялся для каждого участника. Теперь локальный `distancesAt` хранит расстояния для каждого рынка с оплачиваемым спросом. Число поисков ограничено числом таких рынков вместо числа участников. Граф и сортированные списки поставщиков строятся один раз на вызов. Кеш уничтожается после вызова; после изменения состояния следующий вызов строит всё заново.
- Последовательная подготовка: Core и `autonomy.begin` рассчитывали прогноз одного и того же неизменяемого opening state. Core передаёт готовый массив автономному управлению.
- Workers: общий прогноз рассчитывается один раз перед созданием проекций. `project` фильтрует этот массив по рынкам, сохраняя прежние поля сообщений. Worker Pool и объединение результатов сохраняют архитектуру.
- Индексы заменяют повторные поиски земли по провинции, контроллеров и домохозяйств по ID, рецептов, потребностей, котировок и оплаченных запасов. В подготовке домохозяйств списки предприятий и прогнозов заранее группируются по рынку с сохранением порядка.
- `incomingContext` группирует ссылки на грузы по владельцу и товару. Сумма вычисляется из актуальных количеств с прежним `add` и проверкой переполнения. После обработки старых грузов координатор создаёт новый индекс для подготовки покупателей. Индекс не используется после изменения состава грузов.
- Земля, остатки, деньги, секторы и контроллеры читаются через живые ссылки. Их значения не кешируются. Контексты остаются локальными переменными, не добавляются в GameState или JSON. Существующие временные поля Worker-проекций по-прежнему удаляются до сохранения.

## Основания для эквивалентности

BFS сохраняет сортировку соседей, `maxRouteEdges` и проверку `accountingUnitId`. Поставщики сортируются прежним сравнением ID; равная стоимость по-прежнему оставляет первого поставщика. Формулы выгодности и округления, резервирование бюджета и порядок участников не изменены. Индексы используются после валидации уникальности ID. Прогноз остаётся потенциальной возможностью: физическая торговля продолжает проверять реальные склады, деньги, труд и пропускную способность.

## Подготовленные проверки

`tests/economy-performance-equivalence.spec.cjs`: 23 проверки, включая единственного и нескольких поставщиков, точное равенство полной стоимости, повторное использование BFS, валютные единицы, недостижимые рынки, глубину маршрута, домохозяйства, зерно/муку/инструменты, входящие грузы, изменение цен и состава производителей, переполнение, Worker-проекции и один полный прогноз за месяц. Короткие кампании сравнивают **полный сериализованный GameState и отчёт** с движком исходного коммита, включая save/load, миграцию старого сохранения и Workers размером 1, 2 и 3.

Локальный эталон `economy-opportunities-reference.cjs` содержит прежнюю функцию прогноза. Для сравнения всего движка `economy-baseline-loader.cjs` читает исходный коммит через `git show` и загружает отдельный граф CommonJS-модулей без изменения глобального `require.cache`. Требуются Git и доступность этого коммита в локальном репозитории. Fixtures небольшие; глобальная экономика в тестах не запускается.

Тесты **написаны, но не запущены**. Выполнены только `node --check`, `git diff --check` и сборка `npm run build:client`.

## Команды для самостоятельной проверки

Эквивалентность и существующие целевые регрессии:

```powershell
npx playwright test --config playwright.ci.config.cjs tests/economy-performance-equivalence.spec.cjs tests/agricultural-markets.spec.cjs tests/household-economy.spec.cjs tests/economy-workers.spec.cjs tests/economy.spec.cjs
```

Короткое сравнение производительности: выполнить в двух отдельных checkout — исходный коммит и патч — на одном компьютере без ресурсоёмких приложений. Использовать одинаковые исходные данные, seed, число месяцев, Workers и настройки. Следующие команды не запускались агентом:

```powershell
# Checkout d59dfb5; уникальный путь результата, чтобы не перезаписать файл.
node scripts/world-economy-demo.cjs --autonomous --seed 1700 --months 3 --workers 4 --food-feedback on --summary-every 3 --stats perf-v32-before.json
# Checkout с патчем; те же исходные данные и параметры.
node scripts/world-economy-demo.cjs --autonomous --seed 1700 --months 3 --workers 4 --food-feedback on --summary-every 3 --stats perf-v32-after.json
```

Сравнить `times.elapsedMs`, `monthMedianMs`, `monthMaxMs`, `monthP95Ms` и память. Повторить с `--workers 0` в обеих версиях, используя новые имена результатов. Для пользовательской кампании можно в обеих командах заменить `--autonomous` на `--load <одно-и-то-же-сохранение>`; seed тогда берётся из сохранения. Скорость пока не подтверждена измерениями, эквивалентность ожидается по статическому анализу и требует запуска проверок пользователем.

## Изменённые файлы и оставшиеся расходы

Восемь модулей `shared/`: `economy-routes`, `economy`, `autonomous-economy`, `agricultural-resources`, `household-economy`, `economy-observations`, `economy-partitions`, `economy-pool`. Также новый spec, два тестовых helper, CI testMatch, этот документ и собранные JS/source maps для клиента и двух экономических Workers. Интерфейс и сценарии не изменены.

Вне патча остаются полный перебор пар физических предложений и покупателей в координаторе, проверки состояния, клонирование/сериализация и общая стоимость аналитики. Кеш расстояний может хранить по записи на достижимую пару рынков внутри одного вызова; это обмен памяти на устранение повторных обходов. Профилирование и дальнейшие изменения требуют пользовательских измерений.
