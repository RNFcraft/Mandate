# Отчёт А — оптимизация вычислений v3.3

Эталон: коммит `ad7658f2ea35865b288ba991681bd69d27f0a18c`. Этап А действует без `--physical-transport`. Тесты эквивалентности подготовлены перед подключением этапа Б. Симуляции, тесты, профилировщики и бенчмарки агент не запускал; ускорение и идентичность результатов ещё требуют пользовательской проверки.

## Изменения алгоритмов

- `shared/economy-routes.cjs`: валидатор один раз строит множества товаров, участников, рынков и домашних производителей. Поиск продавца или владельца груза выполняется через индекс, а не проход по всему населению для каждой записи. Сохраняются проверки географии, маршрута, валютной единицы, прав собственности и эскроу старого режима.
- `shared/economy-trade.cjs`: аналогичные индексы для потоков, производителей и потребительских товаров.
- `shared/economy.cjs`: физические остатки, использование и потребление агрегируются одним проходом по владельцам и грузам в BigInt вместо повторного прохода по всем грузам для каждого товара. Капитальные балансы индексируются по товару.
- `shared/economy-topology.cjs`: BFS хранит `parent + distance`; полный путь восстанавливается только для выбранной пары. Соседи сортируются прежним порядком. Неизменная топология переиспользуется по точной сигнатуре рынков, денежных единиц и рёбер; межмесячный LRU ограничен 128 деревьями. Индексы конкретной фазы сохраняют нужные деревья до её завершения. Деньги, труд, предложение и транспортная доступность в этом кэше отсутствуют.
- `shared/economy-routes.cjs`: группы поставщиков индексируются по товару и связной компоненте одной денежной единицы. Опустевшие группы выключаются после продажи. Недостижимые группы учитываются в прежних счётчиках отказов без запроса BFS. Внутри компоненты сохраняются ограничение длины маршрута, сортировка предложений, правила цены и равенства. Покупатель с нулевым остатком не исключается: продовольственный заказ может повторно открыться при более длинном горизонте.
- `shared/economy-observations.cjs`, `shared/economy-history.cjs`: месячная история рассчитывает только используемые скалярные наблюдения. Публичные подробные отчёты сохраняют прежний состав.

При N грузах и H домохозяйствах проверка принадлежности теперь требует O(N + H), а не O(N × H). Агрегирование физических остатков требует одного прохода по запасам вместо отдельного полного прохода для каждого товара. BFS больше не создаёт массив полного пути для каждой достигнутой вершины. Число посещений недостижимых и исчерпанных групп должно уменьшиться; размер эффекта пока не измерен.

## Сохранённые инварианты

Остаются транзакционный месячный переход, клонирование подготовленного состояния, все полные проверки перед установкой, кассовая и товарная консервация, проверки безопасных целых чисел и переполнений. Повторные валидации не удалены. Изменения не используют часы или дополнительные RNG draws и не изменяют порядок фаз, труд, цены, приоритеты, потребление, выплаты или торговые возможности старого режима.

`structuredClone` не заменён поверхностным копированием. Его стоимость остаётся отдельной зависимостью: без измерения и доказательства изоляции изменение стратегии клонирования слишком велико для этого этапа. Генерация геометрии, сценарные активы и историческая экономика не изменены.

## Подготовленные проверки

`tests/economy-stage-a.spec.cjs` через расширенный `tests/fixtures/economy-baseline-loader.cjs` загружает из Git замороженный граф модулей эталонного коммита. Проверки сравнивают полную сериализацию GameState, RNG внутри неё, экономический отчёт, порядок потоков и балансы за несколько месяцев для локального, соседнего, двухэтапного и смешанного рынка. Отдельно проверяются продолжение сохранения, отказ при повреждении груза/кассы без частичной установки и включённое профилирование. Эти проверки добавлены в конфигурацию CI, но не запускались.

Разрешённые проверки выполнены успешно: `node --check` для затронутых CommonJS-файлов, `git diff --check`, `npm run build:client`. Это проверка синтаксиса и сборки; экономическую эквивалентность она не доказывает.

## Команды для пользователя

Из корня репозитория; имена результатов должны быть новыми, runner не перезаписывает существующие файлы:

```powershell
npx playwright test --config playwright.ci.config.cjs tests/economy-stage-a.spec.cjs
node scripts/world-economy-demo.cjs --load v33-1710.json --months 1 --workers 0 --summary-every 1 --stats v33-stage-a-1710-1m.json --save v33-stage-a-1710-1m-save.json
node scripts/world-economy-demo.cjs --load v33-1710.json --months 1 --workers 0 --summary-every 1 --profile-economy --stats v33-stage-a-profile-1710-1m.json
```

Для сравнения доступны исходные пользовательские файлы `v33-baseline-1710-1m.json` и `v33-profile-1710-1m.json`. Их содержимое и исходные времена не являются результатами нового кода. Сначала следует проверить эквивалентность; затем сравнить одинаковый месяц, настройки, память и фазы. Не объединять `--profile-economy` и `--benchmark`.
