# Производительность и workers v1

Рендер и симуляция работают независимо. Экономические правила, порядок месячных систем, дневные RNG-вызовы, GameState v2 и save v2 сохранены. Процедурный мир остаётся опциональным синтетическим сценарием; опубликованные сценарии и замороженная география не изменялись.

## Архитектура

- Main thread хранит карту, управление и замороженную проекцию для UI. Единственный GameState находится в `simulation-worker.bundle.js`. `SimulationClient` предоставляет асинхронные `step`, `submit`, `snapshot`, `serialize`, `save`, `load`. Обзорные методы читают последнюю подтверждённую проекцию.
- Протокол v1 использует возрастающие request ID и последовательную очередь. Повторный запрос не выполняет второй commit. Save сериализует согласованное состояние в worker без промежуточных копий мира; Load проверяет envelope и GameState до установки, затем ставит игру на паузу. Неуспешная загрузка сохраняет предыдущую кампанию.
- Часы держат один запрос шага в работе, ограничивают догоняющее время и не накапливают очередь во время расчёта. В режиме worker один запрос часов содержит максимум 28 дней. Дата UI меняется только после подтверждения.
- Месячное сообщение содержит динамические таблицы статистики, цены, население и новые записи. Оно не содержит склады предприятий или весь GameState. Подробности выбранного предприятия запрашиваются отдельно. Установка проекции порционно уступает main thread; статистика обновляет существующие маркеры без повторной генерации точек.
- Статический фон растеризуется в `raster-worker.bundle.js` через OffscreenCanvas. Геометрия передаётся один раз, изменения владельцев и цветов — отдельно. Во время жестов используются предыдущий bitmap и обзорный фон; качественный viewport обновляется после остановки. ImageBitmap закрывается при замене. Недоступность или ошибка raster worker переключает карту на Canvas.
- Городские и производственные маркеры используют пространственные индексы, уровни детализации, устойчивые внутренние точки и общий бюджет до 200 символов. Точный выбор провинции по Path2D сохранён. Общая боковая панель объединяет провинцию, поселения, предприятия и рынок; склад отображается таблицей.

## Экспериментальный пул экономики

`shared/economy-pool.cjs` использует один переносимый алгоритм через браузерные Workers или Node worker_threads. Целый локальный рынок закрепляется за одним исполнителем. Валидатор гарантирует непересекающиеся провинции, один местный трудовой пул и владельца предприятия в том же рынке. Покупки, зарплаты и выплаты не пересекают границу раздела.

Рынки распределяются по весу домохозяйств, предприятий, товаров и автономных контроллеров. Исполнители постоянные и сохраняют свои разделы; последующие входы содержат население, финансирование новых предприятий и новые записи, а не копию глобального мира. Координатор проверяет полное открывающее состояние, локальные результаты проходят закрывающую проверку, затем проверяется канонически объединённая экономика. Население, развитие поселений и итоговая проверка сохраняют прежний последовательный порядок. Clock/RNG/events меняются только после успешной подготовки месяца.

Внутренняя `prepareValidatedMonth` предназначена только для уже проверенного раздела; обычная `prepareEconomyMonth` сохраняет входную проверку. Падение, отмена, timeout или ошибка результата уничтожают спекулятивные разделы. Повторный запрос создаёт исполнителей заново из текущего подтверждённого состояния. Автоматического повторного commit нет. Пауза завершает текущий ограниченный запрос и обрабатывается следующей в очереди.

По умолчанию и для `workers=auto` выбран **0 исполнителей пула**: месяцы последовательно считает отдельный Simulation Worker. Явные размеры 1–8 доступны для эксперимента. В измеренном коротком прогоне лучший размер — 6; у полного прогона преимущество оказалось малым относительно затрат памяти и CPU.

Если Worker отсутствует или его конструктор недоступен, используется переносимый прямой kernel. Этот fallback сохраняет результаты, но месячный расчёт блокирует main thread. После падения уже запущенного Simulation Worker UI останавливает часы; второй независимый GameState автоматически не создаётся.

## Реально выполненные измерения

Машина: AMD Ryzen 7 5700X, 8 ядер / 16 логических процессоров. Браузерный стенд: Playwright Chromium, 1440×900, DPR 1, одна опубликованная география, повторяемые жесты, три холодных/тёплых прогона. Дополнительно проверены цвета и точные попадания при DPR 1 и 2, Canvas и отсутствие Worker.

Исходный p95 рендера при панорамировании: **205–242 мс**, семь пересозданий bitmap и семь задач длиннее 100 мс на прогон. Первый drawImage принудительно завершал накопленную растеризацию. Программный Canvas с `willReadFrequently` оставил длинные кадры; он не выбран. Первый вариант OffscreenCanvas дал p95 **5–6,4 мс** и ноль длинных задач на трёх прогонах. Финальные цифры, включая LOD, месячную проекцию и save/load, находятся в [машинном отчёте](performance-overhaul-results.json). WebGL не потребовался для устранения измеренного узкого места.

После всех изменений итоговый p95 рендера при панорамировании — **6–8,2 мс**, p95 интервала кадров — **16,7–16,8 мс**; в трёх прогонах ноль задач длиннее 50 мс. При максимальной скорости отдельного Simulation Worker p95/p99 кадров — **16,8/33,3 мс**, max — **50,1 мс**; зарегистрированы две задачи 50–100 мс и ни одной длиннее 100 мс. Save/Load полного мира заняли **181/1221 мс** до подтверждения UI. Месячное сообщение в этом стенде — до **7,74 MB в JSON-представлении**, обычное дневное подтверждение — около 322 байт; JSON-размер является диагностической оценкой, а не измерением внутреннего бинарного IPC. Начальная проекция и Load тяжелее месячного обновления. Обработка обзора ещё не свободна от коротких пауз GC/десериализации.

## Воспроизведение

```powershell
npm run build:client
npm run test:ci
npx playwright test --config playwright.performance.config.cjs
node scripts/performance-economy.cjs --months 12 --repeat 3 --sizes 0,1,2,4,6,8 --output tmp/worker-comparison.json
node scripts/performance-economy.cjs --months 600 --sizes 0,6 --output tmp/campaign-comparison.json
node scripts/world-economy-demo.cjs --autonomous --months 120 --workers 6 --benchmark
```

Браузер: `/?scenario=1700&worldEconomy=1&autonomous=1&perf=1&workers=6`. Диагностические переключатели: `raster=canvas`, `simulation=direct`. Без `perf=1` монитор и профилирующие обёртки не устанавливаются. Файлы workers собираются штатными `build:client` и `prestart`; GIS не запускается. Длинный benchmark не входит в CI; история отчётов остаётся годовой, состояние сохранения содержит все данные продолжения.

Основной предел ускорения сейчас — последовательная проверка/объединение состояния, передача результатов и развитие поселений. Дальнейшее уменьшение этих затрат требует отдельного профиля и тех же проверок полного состояния; экономические правила ради скорости не упрощались. Тесты включают фактическое использование восьми исполнителей, перестановку порядка завершения, crash/cancel/retry, переполнение, очередь команд, двойные запросы, сохранение/загрузку и работу UI при расчёте месяца.

Проверки: `npm run build:client` — успешно; `npm run test:ci` — **206 passed**; отдельный performance benchmark — **2 passed**. В CI входят существующие экономические, демографические и географические проверки без запуска GIS. После финальной сборки проверки протокола/workers дали **14 passed**, а проверки загрузки, обратного давления часов и переносимого kernel — **20 passed**; результаты записаны в машинном отчёте.
